# 方法、边界与后续验证

## 1. 预测问题先于模型

旧目标是“这位客户的已知消费是否达到 500”，同时输入已知消费本身。这样的模型会学习标签的构造规则，不能检验未来预测能力。本项目改为一个时间切片：历史交易形成特征，随后固定窗口形成标签。同一个人的多个订单必须由 `customer_unique_id` 汇总。

标签取下单商品毛额，不是净收入。静态订单的最终取消/交付状态可能在截止日后才产生，所以不用于回头筛选历史订单。没有商品明细的订单不可计价，不进入样本；仅有这类订单的客户不在评分人群中。产品类别来自静态表，如果类别曾经修改，仍需要业务侧补充历史快照。

## 2. 覆盖、截尾与观察窗口

设截止时间为 C、窗口长度为 H。历史仅使用时间小于 C 的交易，标签使用 [C, C+H) 的交易。覆盖声明 `data-through` 必须不早于 C+H。即使窗口内某客户没有订单，只能在“数据收集完整”的前提下将标签设为 0。

程序不能通过文件中最后一个购买日期证明采集完整。`data-through` 必须来自采集系统的覆盖记录或数据提供方确认。即使参数检查通过，也不是数据完整性的独立认证。演示覆盖终点固定为 2025-06-30，合成器仅生成此前的订单。

时间以输入文件的本地时间为准，不进行隐藏的 UTC 转换；各表和截止参数须统一且不带时区。截止与窗口终点都是精确时间，示例日期表示当日 00:00。

## 3. 为什么需要三份数据

每位历史客户只有一条记录，按目标标签分层随机划分 60/20/20。候选模型的填补、缩放和拟合仅看训练集；验证集 AP 用来选择模型。选好后用训练+验证集重新拟合，再对留出的测试集评估一次。测试标签或分数不参与选模、阈值或参数搜索。

三候选模型为先验概率基线、带类别权重的逻辑回归与随机森林。如果基线表现最好，程序也会保留它；不会为了好看的结果强制输出复杂模型。正负两类样本太少时直接报错，不给不可解释的 ROC-AUC。

此处并未做滚动回测。客户隔离防止同一人同时进入多个集合，但不等于跨时间验证。它适合展示完整、可审查的基线流程。不能仅凭一次随机留出的 AP 或 AUC 宣称模型可以上线。

## 4. 指标如何阅读

- AP 侧重正类排序；应同时看 `positive_rate`，因为不同标签的 AP 不能脱离正类比例直接比较。
- ROC-AUC 衡量排序；Accuracy/F1/Precision/Recall 由固定的 0.5 阈值产生。
- 类别权重改变学习目标，模型原始分数没有经过校准。营销阈值应该在验证数据上结合触达成本和收益选择。
- 随机森林的 impurity importance 可能受特征分布影响；逻辑回归图展示标准化后的系数。两者都不是因果贡献。
- 合成数据的随机生成机制是人为设定的；该数据只验证运行和信息隔离，不验证现实商业价值。

## 5. 生产化之前应补充的内容

1. 在源系统证明订单覆盖完整，记录字段到达时间，保存历史时点快照。
2. 按多个截止月做时间外验证，并明确客户是否允许跨时间重复出现。
3. 分析商品金额、退款、取消与实际收入的差异，另建净收入目标需要可追溯的会计数据。
4. 用验证数据选择触达阈值、校准分数，再在未来样本上检查稳定性。
5. 评估不同地区/客群的覆盖、误差和营销政策影响，设置数据漂移监控。
